## 失败方式与验证

1. 新正文只在源码存在，安装后丢失：先写公共 CLI 场景，检查两份文档被安装、进入校验指纹；缺失文件时 check 和 apply 均失败且不写入。
2. 旧安装升级后根入口指向不存在的文件，或回退只恢复一部分：用基线提交创建临时旧项目，再通过候选 CLI 升级、check、重复安装、实际回退；保留命令和事务产物，禁止使用真实 home。
3. 抽取或精简意外丢掉已确认条款：比较四条置顶原则、九条 HR 和十条工程原则的字节；归属表核对批准、记忆、冲突暂停及报告格式的最终位置。
4. 拆分导致无条件全量读取或引用递归：静态核对根表的触发条件；只依任务沿相关引用读取，按已读内容避免重复，不声称天然导入。
5. 本地资源与沙箱定位混淆：审阅六类资源的定位、只读与写入、网络和授权边界；不可用不得自动安装、绕过或猜测成功。
6. 适用命令：开发期间只运行新增 CLI 场景和结构检查；结束时执行 validation/tests 完整回归、bundle、任务/TODO、git diff --check。Coach OS 后续使用自身 lint/test，产品工作区只观察和保留。
7. 验收状态逐项随证据更新；独立审查与真实客户端验收单列，不把结构、测试、CI 或发布混为一层。
